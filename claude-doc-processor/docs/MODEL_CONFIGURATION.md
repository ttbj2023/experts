## 模型规格

### Qwen3 VL 8B (视觉模型)

| 项目 | 规格 |
|------|------|
| **提供商** | 阿里云 (Ollama 本地部署) |
| **参数量** | 8B |
| **上下文长度** | 32K 理论，Ollama 默认 2K，需设置 num_ctx |
| **最大输出** | ~4K tokens |
| **主要功能** | 图片理解、OCR、视觉问答 |
| **部署方式** | 本地 Ollama |

**Token 计算**：
```
视觉Token = (图片宽度 × 图片高度) / (32 × 32) + 2
```

| 分辨率 | 视觉Token | 推荐 num_ctx |
|--------|-----------|--------------|
| 720p | ~900 | 8K |
| 1080p | ~2100 | 12K ⭐ |
| 2K | ~3600 | 16K |
| 4K | ~8100 | 24K |

### DeepSeek-Reasoner (文本模型)

| 项目 | 规格 |
|------|------|
| **提供商** | DeepSeek (API) |
| **参数量** | 未公开 |
| **上下文长度** | 128K tokens |
| **最大输出** | 32K/64K tokens |
| **主要功能** | 复杂推理、长文档理解、语义分析 |
| **特点** | Chain of Thought 思考过程 |

**优势**：
- 超长上下文（128K）
- 推理能力强（有思考过程）
- 输出长度大（32K+）
- 适合全局语义理解

## 使用场景

### 视觉任务 (Qwen3 VL)

1. **OCR 识别**
   - 现代文档：temperature 0.05, num_ctx 12288
   - 古典文献：temperature 0.0, num_ctx 16384
   - 家谱：temperature 0.0, num_ctx 20480

2. **图片分析**
   - 类型判断：temperature 0.0, num_ctx 6144
   - 详细描述：temperature 0.2, num_ctx 6144

### 文本任务 (DeepSeek-Reasoner)

1. **语义匹配**
   - 上下文：全文（可能很长）
   - 温度：0.1
   - 超时：300s（思考时间长）

2. **排版优化**
   - 上下文：分段处理（每段 < 50K）
   - 温度：0.1
   - 超时：300s

3. **内容整理**
   - 上下文：全文
   - 温度：0.1
   - 超时：300s

## 性能优化

### Qwen3 VL 优化

1. **上下文窗口**
   - 不要设置过大（影响速度）
   - 根据图片分辨率选择合适的 num_ctx
   - 使用 OLLAMA_NUM_CTX 环境变量

2. **批处理**
   - 单页处理：速度快
   - 多页合并：需要更大上下文

### DeepSeek-Reasoner 优化

1. **超时设置**
   - 推理模型思考时间长
   - 建议 timeout: 300s (5分钟)

2. **分段处理**
   - 超长文档分段处理（每段 < 50K）
   - 避免单次请求过大

3. **缓存利用**
   - 相同内容会被缓存
   - 缓存价格是 1/10

## 常见问题

### Q: 为什么不用 Qwen3 VL 做文本任务？

A: Qwen3 VL 是视觉模型，虽然也能处理文本，但：
- DeepSeek-Reasoner 推理能力更强
- 上下文更长（128K vs 32K）
- 输出更长（32K vs 4K）
- 有思考过程，更适合复杂理解

### Q: 为什么 OCR 不用 DeepSeek-Reasoner？

A: DeepSeek-Reasoner 不支持图片输入。必须先用视觉模型（Qwen3 VL）识别图片。

### Q: 思考过程占用多少 token？

A: 根据任务复杂度：
- 简单任务：~2-4K tokens
- 中等任务：~4-8K tokens
- 复杂任务：~8-16K tokens

### Q: 如何平衡速度和质量？

A:
- **速度优先**：降低 num_ctx，提高 temperature
- **质量优先**：提高 num_ctx，降低 temperature，增加 timeout
- **平衡模式**：使用推荐配置
