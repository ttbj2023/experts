## 模板概述

### 设计理念

标书模板严格按照**国内政府招标文件规范**设计，确保生成的文档符合以下标准：

✅ **GB/T 9704-2012** 《党政机关公文格式》
✅ **GB/T 15834-2011** 《标点符号用法》
✅ **GB/T 15835-2011** 《出版物上数字用法》

### 核心特点

| 特点 | 规范要求 | 模板实现 |
|------|----------|----------|
| **字体** | 中文宋体、西文Times New Roman | ✅ 严格遵循 |
| **标题字体** | 黑体、可加粗 | ✅ 一级标题黑体加粗 |
| **颜色** | 纯黑色（#000000），禁止其他颜色 | ✅ 正文、标题、边框均为纯黑 |
| **正文加粗** | 禁止正文加粗（仅标题可加粗） | ✅ 五级标题及以上不加粗 |
| **字号** | 小四号正文（12pt）、三号标题（16pt） | ✅ 符合标准 |
| **行距** | 1.5倍行距或固定22磅 | ✅ 1.5倍行距 |
| **首行缩进** | 2字符（2em） | ✅ 自动应用 |
| **页边距** | 左侧2.7cm（装订侧）、其他2.2cm | ✅ 符合装订要求 |

### 与其他模板的区别

| 对比项 | 标书模板 | 学术模板 | 商务模板 | 技术模板 |
|--------|----------|----------|----------|----------|
| **颜色方案** | 仅纯黑 | 黑色 | 蓝色主题 | GitHub蓝 |
| **字体选择** | 宋体为主 | 宋体+Times New Roman | Calibre+黑体 | Consolas |
| **正文加粗** | ❌ 禁止 | ✅ 允许 | ✅ 允许 | ✅ 允许 |
| **标题样式** | 黑体加粗 | 黑体加粗 | Calibre加粗 | 粗体 |
| **表格样式** | 纯黑边框、无背景色 | 简约边框 | 蓝色边框 | 灰色主题 |
| **左侧边距** | 2.7cm（装订） | 2.54cm | 2.54cm | 2.54cm |

## 格式规范

### 字体规范

#### 1. 正文

```yaml
中文字体: 宋体
西文字体: Times New Roman
字号: 小四号（12pt）
颜色: #000000（纯黑）
行距: 1.5倍
首行缩进: 2字符（2em）
```

#### 2. 标题

| 标题级别 | 字号 | 字体 | 对齐 | 加粗 | 编号样式 |
|----------|------|------|------|------|----------|
| **一级标题** | 三号（16pt） | 黑体 | 居中 | ✅ | 中文数字：一、二、三 |
| **二级标题** | 小三号（15pt） | 黑体 | 左对齐 | ✅ | 括号中文：（一）、（二） |
| **三级标题** | 四号（14pt） | 黑体 | 左对齐 | ✅ | 阿拉伯数字：1、2、3 |
| **四级标题** | 小四号（12pt） | 黑体 | 左对齐 | ✅ | 括号阿拉伯：(1)、(2)、(3) |
| **五级标题** | 小四号（12pt） | 黑体 | 左对齐 | ❌ | 圆圈数字：①、②、③ |
| **六级标题** | 小四号（12pt） | 黑体 | 左对齐 | ❌ | 无编号 |

#### 3. 表格

```yaml
表题字号: 三号（16pt）粗体居中
表题位置: 表格上方
内容字号: 五号（10.5pt）
边框宽度: 0.75磅（0.75pt）
边框颜色: #000000（纯黑）
单元格内边距: 4pt
表头背景: #FFFFFF（白色，无背景色）
```

#### 4. 图片

```yaml
图题字号: 三号（16pt）粗体居中
图题位置: 图片下方
图片对齐: 居中
最大宽度: 85%页面宽度
编号格式: 图1、图2、图3...
```

### 页面布局

```yaml
纸张大小: A4（210mm × 297mm）
页边距:
  上边距: 2.2cm
  下边距: 2.2cm
  左边距: 2.7cm  # 装订侧，稍大
  右边距: 2.2cm
```

### 段落间距

```yaml
段前间距: 0pt
段后间距: 0pt  # 标书正文通常段前段后均为0
```

### 标题间距

| 标题级别 | 段前间距 | 段后间距 |
|----------|----------|----------|
| 一级标题 | 18pt | 12pt |
| 二级标题 | 14pt | 10pt |
| 三级标题 | 12pt | 8pt |
| 四级标题 | 12pt | 6pt |
| 五级标题 | 12pt | 6pt |

## 使用指南

### 基本用法

#### 1. 转换单个文件

```bash
./convert-md-to-html.py tender_doc.md --template tender -o output/
```

#### 2. 查看可用模板

```bash
./convert-md-to-html.py --list-templates
```

输出中应包含：

```
[2] tender (投标文件 v1.0.0)
  描述：严格符合国内标书编制规范，宋体纯黑色，传统中文排版，首行缩进2字符，固定行距22磅
```

#### 3. 转换为DOCX

```bash
./convert-md-to-html.py tender_doc.md --template tender --to-docx
```

这将自动调用LibreOffice将HTML转换为DOCX格式。

## 常见问题

### Q1: 为什么标书模板禁止使用彩色？

**A**: 根据国家招标文件规范（GB/T 9704-2012），标书必须使用纯黑色打印，以确保：
- 打印效果一致
- 避免色彩干扰
- 符合档案管理要求
- 便于黑白复印存档

### Q2: 投标函的"仿宋_GB2312"字体如何设置？

**A**: 投标函的字体设置有两种方式：

**方式1：在Word中手动设置**
1. 打开生成的DOCX文件
2. 选中投标函内容
3. 字体→选择"仿宋_GB2312"
4. 字号→设置为14pt

**方式2：在HTML中添加样式**
```html
<p style="font-family: '仿宋_GB2312'; font-size: 14pt;">
投标函内容...
</p>
```

### Q3: 表格内容显示为12pt而不是10.5pt？

**A**: 这可能是以下原因：

1. **Word缓存问题**
   - 关闭Word文档
   - 清除Word缓存（%appdata%\Microsoft\Templates）
   - 重新打开文档

2. **样式优先级问题**
   - 在Word中右键表格→表格属性
   - 查看"样式"是否为"Normal"
   - 尝试清除格式后重新应用

3. **手动覆盖**
   - 选中表格内容
   - 字号→选择"五号"或"10.5pt"

### Q4: 如何实现标书的章节自动编号？

**A**: Markdown转HTML后，可以在Word中设置自动编号：

1. 选中所有一级标题
2. 右键→段落→项目符号和编号
3. 选择"一、二、三"样式
4. 重复操作设置二级、三级标题编号

或直接在Markdown中使用手动编号：

```markdown
# 一、项目背景

## （一）项目概述

### 1、建设目标

#### （1）具体目标
```

### Q5: 生成的DOCX文件左侧边距不是2.7cm？

**A**: 检查以下几点：

1. **确认模板加载成功**
   ```bash
   ./convert-md-to-html.py input.md --template tender --list-templates
   ```
   应显示"使用模板: 投标文件 (v1.0.0)"

2. **检查HTML中的@page规则**
   ```bash
   grep "@page" output.html
   ```
   应显示：`margin: 2.2cm 2.2cm 2.2cm 2.7cm;`

3. **Word中检查页面设置**
   - 布局→页边距→自定义
   - 确认左：2.7cm

### Q6: 标书打印时有哪些注意事项？

**A**: 标书打印要求：

| 项目 | 要求 | 说明 |
|------|------|------|
| **打印机** | 激光打印机 | 喷墨打印机可能晕染 |
| **纸张** | 70-80g A4纸 | 标准复印纸 |
| **墨粉** | 黑色墨粉充足 | 确保打印颜色均匀 |
| **单双面** | 根据招标文件要求 | 通常双面打印 |
| **装订** | 左侧装订 | 距离左边缘1cm处 |
| **页码** | 底部居中 | 阿拉伯数字1、2、3... |

## 最佳实践

### 1. 文档结构设计

✅ **推荐结构**：
```
封面 → 投标函 → 投标一览表 → 技术方案 → 实施计划 → 售后服务 → 资质文件 → 授权委托书
```

❌ **避免**：
- 缺少投标函或授权委托书
- 技术方案和商务方案混在一起
- 缺少必要的证明材料

### 2. 表格设计

✅ **推荐做法**：
- 所有数值保留2位小数
- 使用千分位分隔符（3,500,000.00）
- 表题使用"表X："格式
- 合计行使用加粗

```markdown
| 序号 | 项目 | 金额（元） |
|------|------|------------|
| 1 | 平台开发 | 3,500,000.00 |
| 2 | 硬件采购 | 4,200,000.00 |
| **合计** | | **7,700,000.00** |

**表1：项目报价汇总表**
```

❌ **避免**：
- 数量不保留小数（如：3500000）
- 缺少表题
- 合计行不加粗

### 3. 标题层级

✅ **推荐做法**：
- 最多使用5级标题
- 使用中文数字编号（一、二、三）
- 标题简洁明确（不超过20字）

```markdown
# 四、技术方案

## （一）总体架构

### 1、基础设施层

#### （1）服务器配置

##### ① 内存要求
```

❌ **避免**：
- 使用6级以上标题
- 标题过长（如："关于XX市智慧城市建设项目中数据中心建设的具体技术实现方案详细说明"）
- 混用编号样式

### 4. 代码块使用

✅ **推荐做法**：
- 仅在技术方案部分使用代码块
- 指定编程语言（便于语法高亮）
- 代码不宜过长（不超过20行）

````markdown
```java
public class ProcessEngine {
    public void start() {
        System.out.println("启动");
    }
}
```
````

❌ **避免**：
- 在非技术章节使用代码块
- 代码块内容超过200行
- 不指定语言

### 5. 格式一致性

✅ **推荐做法**：
- 统一使用中文标点（逗号、句号、分号）
- 统一数字格式（阿拉伯数字123）
- 统一日期格式（2024年12月15日）
- 统一金额格式（¥12,345.00或12,345.00元）

❌ **避免**：
- 中英文标点混用（如：你好，world。）
- 数字格式不统一（如：100和壹佰）
- 日期格式混乱（如：2024-12-15和2024年12月15日）

### 6. 转换流程

**标准流程**：

```bash
# 1. 编写Markdown
vim tender_doc.md

# 2. 转换为HTML
./convert-md-to-html.py tender_doc.md --template tender -o output/

# 3. 检查HTML（可选）
firefox output/tender_doc.html

# 4. 转换为DOCX
./convert-md-to-html.py tender_doc.md --template tender --to-docx

# 5. 用Word打开检查
libreoffice output/tender_doc.docx
```

**验证清单**：

- [ ] 字体：宋体（正文）、黑体（标题）
- [ ] 字号：小四（正文）、三号（标题1）
- [ ] 颜色：纯黑色#000000
- [ ] 首行缩进：2字符
- [ ] 行距：1.5倍
- [ ] 页边距：左侧2.7cm
- [ ] 表格字号：五号（10.5pt）
- [ ] 表题字号：三号（16pt）
- [ ] 段前段后：0pt
